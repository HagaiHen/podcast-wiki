Tests-First AI Coding

Summary: When agents write the code, the bottleneck moves from writing code to knowing whether it is right, so the tests become the real specification. Sam's team has humans write failing tests first and freezes them so the agent cannot edit them, which nearly eliminated "passed but wrong" incidents and makes review short. Frozen tests also act as a stop condition that keeps agent cost down. Priya disagrees for most teams: she lets the agent write code and tests together, then reviews the tests and uses mutation testing, keeping tests-first for well-specified backend logic.

Key ideas

  • Writing code got cheap; verifying it got expensive. Humans write failing tests, the agent codes until they pass (build-log--tests-before-agents, sam)
  • An agent that writes its own tests "grades its own homework" and can write a test that matches its bug; freeze tests/ during agent tasks (build-log--tests-before-agents, sam)
  • Tests-first is slower the first week, then faster, because reviewers read small tests instead of 600 lines of generated code (build-log--tests-before-agents, sam)
  • If agent PRs keep getting reverted, the tests are too weak: "the agent is only as good as the definition of done you give it" (build-log--tests-before-agents, sam)
  • Frozen tests double as a stop condition: the agent stops when tests pass instead of polishing forever (build-log--cost-of-agents, sam)
  • Agent writes code and tests together; humans review the tests afterwards, and mutation testing flags weak tests (signal-and-noise--ai-code-review-in-practice, priya)

    • Disagreements & open questions

  • Write tests first? Sam says humans must write and freeze the tests first, or the agent grades its own homework (build-log--tests-before-agents, sam). Priya calls it overrated for most teams: slow up front, and for UI or exploratory work you don't yet know the right behavior; a human reading agent-written tests "closes most of that gap" (signal-and-noise--ai-code-review-in-practice, priya).
  • Common ground: both agree on tests-first for well-specified backend logic. Open: where exactly the line sits for UI and product work.

    • Takeaways

  • ☐ Pick one repo, adopt "tests first, tests frozen", and track the agent-PR revert rate (build-log--tests-before-agents)
  • ☐ If the agent writes its own tests, run mutation testing to catch weak ones (signal-and-noise--ai-code-review-in-practice)
